# gpthreejs Agent Guide

gpthreejs is a code-first image-to-Three.js pipeline. Protect its core promise:
reference evidence becomes editable procedural TypeScript, not opaque mesh output
or unsupported claims.

## Direction

- Keep the Python engine small, deterministic, and testable.
- Keep generated Three.js source readable, diffable, and runtime-friendly.
- Treat Sense Packs, Feature Ledgers, Form Blueprints, metrics, and critique
  journals as product contracts.
- Prefer explicit gates over optimistic generation.
- Admit uncertainty from single-view references, hidden sides, likeness, and
  organic deformation.

## Values

- Evidence before aesthetics.
- Source ownership before asset opacity.
- Small contracts before broad rewrites.
- Honest failure before shallow success.
- Runtime budgets before decorative complexity.

## Documentation

- Keep durable project documentation under `docs/`.
- Keep root-level documents limited to repository entry points such as
  `README.md`, `SKILL.md`, `LICENSE`, and this `AGENTS.md`.
- Use lowercase kebab-case for every markdown file under `docs/`, including
  nested folders.
- Write documentation in English by default.
- `README.md` may include localized summaries in Korean, Chinese, and Japanese.

## Implementation

- Preserve existing CLI behavior unless the change explicitly migrates it.
- Add dependencies only when they remove real implementation risk.
- Keep generated or cache-heavy folders out of git.
- Run focused tests for changed behavior before claiming completion.
- For documentation-only changes, verify links, naming, and language policy.
